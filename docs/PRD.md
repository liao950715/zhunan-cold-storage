## 1. 專案背景與目標

### 1.1 案例背景
竹南冷凍倉儲公司位於苗栗縣竹南鎮，擁有兩座冷凍庫，儲存約 20 種蔬果。公司於盛產期採購，非盛產期出售。商品增加及搬運人力減少後，商品被隨意堆放，出貨時難以找到；庫存主要依賴李太太的記憶，曾發生明明記得有五籠甘藍菜，卻找不到、日後才發現商品已受損的情況。

### 1.2 問題與對策
| 問題編號 | 現有問題 | 系統對策 |
|---|---|---|
| P-01 | 商品隨意堆放、位置不明 | 2D 冷凍庫平面圖、貨架及儲位 |
| P-02 | 知道有庫存卻找不到 | 商品／批次／儲位搜尋與定位 |
| P-03 | 數量依賴人工記憶 | 入出庫、盤點與庫存明細 |
| P-04 | 舊批次久放 | 批次、效期提醒與 FEFO 建議 |
| P-05 | 損壞未即時登記 | 直接報損與歷史紀錄 |
| P-06 | 庫存差異難追查 | 不可任意抹除的異動紀錄 |
| P-07 | 過度集中於負責人 | 工作人員帳號與日常操作權限 |

**產品目標：** 隨時掌握「有什麼、多少、在哪裡、哪批先處理、數量為何改變」。核心情境是快速找出案例中失蹤的五籠甘藍菜。

## 3. 功能需求與業務規則

### FR-001｜登入與角色
帳號密碼登入；管理員與工作人員角色；登入後按角色提供權限。工作人員可新增商品、編輯倉庫配置，不可核准盤點或管理使用者。

### FR-002｜商品管理
新增、編輯、查詢及停用商品。欄位：商品 ID、名稱、類別、主要計量單位、低庫存警戒值、效期提醒天數、狀態、備註。每種商品自行設定單位（如籠、箱、公斤），不同單位不可直接合計。

### FR-003｜批次管理
每次新入庫自動產生唯一批次編號；記錄商品、入庫日期、預計到期日、原始數量。同商品可有多批次，同一批次可分布於多個儲位。批次編號不得重複。

### FR-004｜冷凍庫與貨架
第一版有兩座冷凍庫 A、B，各自具有平面圖、貨架與儲位。倉庫真實尺寸及貨架初始數量屬示範配置，須可編輯，不宣稱為案例原始資料。

### FR-005｜B+ 可編輯 2D 平面圖
顯示倉庫邊界、入口、通道、貨架、儲位及占用狀態。一般模式可點選查看、入庫、出庫、搬移及搜尋定位；配置編輯模式允許管理員與工作人員新增貨架／儲位、拖曳貨架及儲位圖形調整位置、修改配置並儲存。**拖曳只用於布局編輯；商品入出庫與搬移仍採點選，不拖曳商品。** 平面圖幾何移動不得改變商品的庫存歸屬或數量。有庫存儲位不可直接刪除；刪除貨架須檢查其下儲位。

### FR-006｜單一商品儲位
每儲位同時間僅能存放一種商品，但可含該商品多個批次；不同商品不可混放。儲位清空後才可改存另一商品。

### FR-007｜依儲位與商品設定容量
容量設定與「儲位＋商品」關聯；入庫或搬移超量必須拒絕，原庫存不得部分改動；不同單位不直接混算。若容量配置修改會低於目前占用，應拒絕直接生效或要求先處理庫存（具體互動於技術設計定義）。

### FR-008｜雙入口入庫
入口 A：搜尋商品→填入庫資訊→點選儲位→確認。入口 B：平面圖點選儲位→選商品→填資訊→確認。商品不存在時，工作人員可於入庫流程直接新增並返回原流程。兩入口共用同一套後端業務規則。

### FR-009｜入庫資料
必填：商品、正數數量、預計到期日、儲位分配。入庫日期預設當日可修改；單位自動帶入；批次自動產生；操作者及操作時間自動記錄；備註選填。實際保存期限由使用者確認，不由系統憑空推定。

### FR-010｜多儲位分配
同一筆入庫可分配至多個儲位／兩座冷凍庫。分配量總和必須等於入庫量；各儲位均須通過單一商品、容量驗證；批次、庫存和異動紀錄須原子性成功或全部失敗。

### FR-011｜雙入口出庫
入口 A：搜尋商品→輸入數量→查看 FEFO 建議→確認批次及儲位。入口 B：點選儲位→選批次→輸入數量→確認。不得只扣商品總量，必須扣正確批次與儲位。

### FR-012｜FEFO 建議與人工確認
依預計到期日早晚提出先到期先出（FEFO）建議；使用者可選擇不同批次並確認。不得出庫超過可用庫存。

### FR-013｜部分數量搬移
可指定同一批次的部分數量，從來源儲位移往目的儲位；檢查來源庫存、目的商品限制與容量；成功後來源減少、目的增加、總量不變，留下來源／目的／批次／數量／操作者紀錄。搬移是實物作業紀錄，不可因布局圖形位移自動觸發。

### FR-014｜直接報損
工作人員可直接登記商品、批次、儲位、報損數量與原因；確認後立即扣可用庫存並留存操作者與時間。報損量不得超過可用庫存。本版不包含待檢查隔離審核流程。

### FR-015｜盤點與管理員核准
工作人員提交實際清點數量及差異，未核准前不更新正式庫存；管理員核准或退回。核准時重新確認盤點基準與目前庫存，避免舊盤點覆蓋後續入出庫。只有管理員能核准。

### FR-016｜庫存異動
保留 IN、OUT、DAMAGE、TRANSFER、ADJUSTMENT 五類；至少記錄商品、批次、數量、異動前後資訊、儲位、操作者與時間。歷史紀錄不因改名或布局調整失去追溯性。

### FR-017｜Dashboard
顯示商品／批次／儲位統計、效期提醒、低庫存提醒與入庫／出庫／搜尋快捷操作。不得將不同單位數量不合理相加為一個總數。

### FR-018｜商品個別提醒設定
各商品分別設定效期提醒天數及低庫存警戒值。效期依批次預計到期日計算；低庫存依商品可用總量計算。到期提醒不等於自動宣告報廢。

### FR-019｜搜尋與平面圖定位
可依商品名稱、批次編號、儲位編號搜尋；顯示所有匹配的批次、數量及位置；點選結果切換到相應冷凍庫，並高亮所有相關儲位。

### FR-020｜庫存異動復原（v1.1 新增）
**權限**：僅管理員可執行復原；工作人員可查看異動與復原紀錄但不得執行；前後端均驗證。
**入口**：異動紀錄頁每筆提供「復原這筆操作」按鈕；按下後顯示原始異動資訊（商品、批次、儲位、原始數量）、預計復原的庫存變化、復原原因輸入（必填）、確認與取消。介面簡約明亮，不用只有圖示的按鈕。
**規則**：可復原入庫、出庫、報損、搬移、已核准的盤點調整。復原以**新增反向異動（REVERSAL）**達成，不得刪除或覆寫原始紀錄；保留原始商品、批次、儲位。
**完整性**：復原前重新檢查目前庫存、原始批次與儲位（仍啟用）、儲位容量、單一商品限制、後續異動的影響、是否已復原；無法安全恢復即拒絕並說明原因。庫存更新與復原紀錄同一交易，不得部分成功。
**防重複**：同一筆原始異動只能復原一次（資料庫唯一約束＋交易）。
**紀錄**：新增異動類型 `REVERSAL`，關聯原始異動（`reversalOfId`）、復原者（`operatorId`）、時間（`createdAt`）、原因（`reversalReason`）。

## 5. 資料需求與關係
本節是**概念資料模型**，實際資料表與欄位型別由技術規格決定。

| 實體 | 資料需求 |
|---|---|
| User | 帳號、密碼雜湊、角色、狀態 |
| Product | 名稱、類別、單位、低庫存值、提醒天數、狀態 |
| Batch | 商品、入庫日期、到期日、原始入庫量、唯一編號 |
| Warehouse | 倉庫識別碼、名稱及布局 |
| Rack | 所屬倉庫、編號、圖形位置 |
| Location | 所屬貨架、識別碼、位置、狀態 |
| LocationCapacity | 儲位、商品、可容納數量 |
| Inventory | 批次、儲位、目前可用數量 |
| StockMovement | 類型、來源／目的、數量、前後狀態、操作者、時間 |
| Stocktake／StocktakeItem | 盤點明細、基準數量、實盤量、差異、審核狀態 |

關係：Warehouse→Rack→Location；Product→Batch→Inventory；Location→Inventory；User→StockMovement／Stocktake。

**不變量：** 庫存不得負數；任何儲位不得混放不同商品或超容量；搬移保持商品總量不變；庫存更新與異動紀錄必須是同一個資料庫交易；盤點須核准才能調整。
