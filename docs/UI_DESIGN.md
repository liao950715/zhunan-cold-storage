# UI／UX 設計方案（UI_DESIGN.md）

專案：竹南冷凍倉儲庫存管理系統｜版本：v0.1（設計提案，2026-09-23）
理念：**Simple, Clear, Calm, and Accessible.** 主要使用者：李太太與倉庫工作人員（含不熟悉電腦的中老年使用者）。
原則：只改前端呈現，不動 PRD 業務規則、資料庫與 API。

---

## 1. 現況分析（2026-09-23 版介面）

已完成的第一輪簡化（commit d2e94f4）：固定左側選單、18px 基準字、52px 按鈕、單欄步驟表單、首頁「找貨→入庫／出庫→需要處理」。

仍存在的問題：

| # | 問題 | 影響 |
|---|---|---|
| A1 | 主色 `#175CD3` 偏高飽和，選單整格深藍 | 視覺偏「科技感」，與「安靜、溫和」目標不符 |
| A2 | 選單用 emoji 圖示 | 各平台長相不一、不夠簡約 |
| A3 | 搬移／報損／盤點／紀錄／商品／設定仍是密集表格 | 與入出庫的步驟式體驗不一致 |
| A4 | 平面圖儲位只寫代碼與「商品 數量」，空儲位沒有文字 | 「儲位狀態不能只靠顏色」未完全達成 |
| A5 | 平面圖「調整貨架配置」與一般檢視在同一畫面切換 | 誤觸風險低但仍在同一頁；需更明確的模式提示 |
| A6 | 手機版尚未實機驗證 | 平面圖縮放、選單橫向捲動待確認 |
| A7 | 字體依系統預設 | 各機器字形不一致 |

## 2. Design System

### 2.1 色彩（依需求指定，經對比度檢查）

| 用途 | 色碼 | 說明 |
|---|---|---|
| 主背景 | `#FAFAF7` | 暖白 |
| 次背景 | `#F0F2F1` | 區塊底、統計格 |
| 卡片 | `#FFFFFF` | 白色卡片、極淡陰影 |
| 主要文字 | `#303735` | 對比 11.6:1 |
| 次要文字 | `#626B68` | 對比 5.5:1（可用於 14px 以上輔助文字） |
| 主要操作色（品牌） | `#7297AC` | 用於選中狀態底色、連結、外框、圖示 |
| **主要按鈕底色** | `#5A8199`（品牌色加深） | ⚠️ `#7297AC` 配白字對比僅 3.1:1，中老年使用者不易讀；主要按鈕改用加深一階，白字對比 4.6:1。**需確認** |
| 淺藍背景 | `#E8F0F4` | 選中列、提示框、步驟編號底 |
| 成功 | 底 `#DCE8E2`／字 `#2F5D46` | 一律加文字「完成」「有貨」 |
| 警告 | 底 `#EEDDC7`／字 `#7A4B1E` | 一律加文字「注意」「剩 3 天」 |
| 錯誤／已過期 | 底 `#F3DEDC`／字 `#8C3B32` | 一律加文字「無法執行」「已過期」 |
| 線條 | `#DDE2E0` | 分隔線、輸入框外框 |

禁止：深色側欄、大面積深色、漸層、霓虹、高飽和、玻璃擬態、花俏動畫、只靠顏色表狀態。

### 2.2 字體

- 主字體：**芫荽 Iansui**（`web/public/fonts/Iansui-Regular.woff2`，SIL OFL 1.1）；後備 Noto Sans TC → Microsoft JhengHei → system-ui。
- 只有 Regular 一個字重：粗體以 `font-weight: 700` 由瀏覽器合成，用在數量／儲位／標題；若合成粗體不理想，改以「字級放大＋主色」強調。
- 字級：內文 18px、表單標籤 16–18px、按鈕 18px、頁標題 28px、重要數字 28–36px、輔助文字 ≥ 14px。

### 2.3 間距與形狀

- 8px 基準；卡片內距 20px；卡片間距 20px；按鈕間距 12–16px。
- 圓角：按鈕／輸入框 10px、卡片 14px。
- 陰影：卡片僅 `0 1px 2px rgba(0,0,0,.04)`；其餘不加。

### 2.4 圖示

線條式 SVG（2px 描邊、圓端），24px 網格，固定搭配文字；已建立 `web/src/components/icons.tsx`（首頁、搜尋、入庫、出庫、平面圖、搬移、報損、盤點、紀錄、商品、設定、登出、勾、箭頭）。

### 2.5 元件規格

| 元件 | 規格 |
|---|---|
| 主要按鈕 `.btn-primary` | 52px 高、深品牌底白字、文字為動作（「確認入庫」） |
| 次要按鈕 `.btn` | 52px 高、白底細框 |
| 小按鈕 `.btn-sm` | 40px 高，只用於列表列內動作 |
| 輸入框 `.input` | 52px 高、標籤固定在上方、聚焦淺藍外框 |
| 步驟區塊 `Step` | 圓形編號（完成變勾）＋標題＋內容 |
| 訊息 `Message` | 底色＋前綴文字「完成：／注意：／無法執行：」 |
| 狀態標籤 `tag-*` | 底色＋文字，永不單獨用色點 |
| 核對頁 | 大字摘要、兩個按鈕固定位置：左「返回修改」右「確認○○」 |

## 5. 入庫／出庫 Wireframe

### 5.1 快速入庫（單欄五步）

```
入庫                                        照順序填好，最後核對再入庫
① 選擇商品      [ 輸入商品名稱來找… ] [找不到？新增商品]
                ┌ 甘藍菜（籠）   ┐  ← 點選即選中，選中列淺藍底
                └ 高麗菜（籠）   ┘
② 輸入數量      [ 30 ] 籠
③ 確認到期日    [ 2026/10/23 ]   請依實際保存期限填寫
④ 選擇放置位置  [ A-01-03　空（可放 20） ▾ ]
                [分到其他儲位]
▸ 其他資料（入庫日期、備註）
⑤ 核對資料並入庫
   甘藍菜 30 籠，放在 A-01-03，到期 2026/10/23
   [ 下一步：核對並入庫 ]        ← 未填完時此處寫「還差：選擇商品、輸入數量」
```
核對頁：
```
確認入庫                         請核對下面的資料
┌───────────────────────────────┐
│ 甘藍菜，入庫 30 籠             │ 26px
│ 放在 A 庫・A-01-03            │ 22px
│ 到期日 2026/10/23             │ 20px
└───────────────────────────────┘
[ 返回修改 ]            [ 確認入庫 ]
```
完成頁：「✓ 入庫完成」＋摘要＋「再入庫一筆／查看庫存／回首頁」。

### 5.2 從儲位入庫
平面圖點儲位 → 側欄「放貨到這裡（入庫）」→ 入庫頁第 ④ 步已填、若儲位有商品第 ① 步也已填 → 只需填數量與到期日。

### 5.3 出庫（要出什麼 → 要出多少 → 到哪裡拿 → 確認）

```
① 要出什麼？    [ 甘藍菜（籠） ]   目前有 16 籠，分在 3 個儲位
② 要出多少？    [ 8 ] 籠
③ 到哪裡拿？    系統建議優先出即將到期的貨（先到期先出）；不合適可按「調整」
                從 A-01-03 取 4 籠      這裡有 4 籠・到期 2026/10/23・批次 B20260923-001
                從 A-01-04 取 4 籠      這裡有 7 籠・到期 2026/10/23・批次 B20260923-001
                [調整取貨位置或數量]   合計 8 籠
④ 確認出庫      甘藍菜 共 8 籠，從 A-01-03、A-01-04 取
                [ 下一步：核對並出庫 ]
```
核對頁同入庫格式：「甘藍菜，出庫 8 籠／從 A-01-03 取 4 籠／從 A-01-04 取 4 籠」。


## 9. 中老年使用者困惑點檢查與簡化

| 可能困惑 | 現況 | 簡化方式 |
|---|---|---|
| 「批次」是什麼？ | 各頁都顯示批次號 | 主句只講商品、數量、位置；批次號與到期日縮小放旁邊，說明「同一天進的貨算一批」 |
| 到期日要自己算 | 預設 30 天後 | 提供「7 天／14 天／30 天／自訂」快速鍵，仍由使用者確認 |
| 出庫建議看不懂 | 「系統建議優先出即將到期的貨」 | 每列加「（最早到期）」標籤；改選時說明「你改成先出 A-01-04 的貨」 |
| 入庫分兩個儲位不知道怎麼分 | 「分到其他儲位」展開 | 展開後自動把剩餘數量填到第二格；合計不符時紅字寫「還有 10 籠沒分配」 |
| 儲位代碼 A-01-03 難記 | 只顯示代碼 | 代碼旁加「A 庫 1 號架 3 格」白話，平面圖高亮同步 |
| 找不到「其他作業」裡的功能 | 收在展開選單 | 首頁「需要處理」直接給按鈕（去處理／優先出貨／查看盤點），不必進選單 |
| 錯誤訊息看不懂 | 後端已回中文原因 | 統一格式「無法○○：原因。請…」，並在對應欄位旁重複顯示 |
| 按錯扣錯庫存 | 核對頁＋兩個按鈕 | 核對頁按鈕文字明確（「確認出庫」），並在完成頁提供「這筆做錯了？」→ 引導到搬移／盤點，不提供刪除紀錄 |
| 手機上誤拖貨架 | 一般模式已停用拖曳 | 保持；編輯模式加醒目提示列與「取消」 |
| 看不清楚 | 18px 基準 | 加「文字放大」開關（記在瀏覽器），一鍵切到 20px 基準 |

## 10. 實作順序建議（待確認後執行）

1. Design token 改色（§2.1）＋選單選中樣式（低風險、全站受益）。
2. 平面圖儲位文字與圖例、編輯模式提示列（PRD 核心功能）。
3. 搬移／報損步驟化；盤點、紀錄卡片化。
4. 到期日快速鍵、儲位白話說明、文字放大開關。
5. 手機／平板實機檢查。

以上不修改任何後端、資料庫或 API；所有驗證規則仍由後端執行。


## 2026-09-24 審查後調整（手機／中老年操作）

- **平面圖兩種看法**：手機（<768px）預設「大字列表」（每個儲位一個 64px 高的按鈕，代碼 20px、商品數量 18px、狀態文字必附），可切換「平面圖」；平面圖有「放大＋／縮小－／回到 <已選儲位>」，放大後可滑動，字一起放大。選擇會記在瀏覽器。
- **搬移**：目前步驟釘頂；起點／終點摘要手機並排精簡；選好起點自動帶到數量欄、選好終點自動帶到確認區；手機底部固定主要按鈕（避開安全區）。
- **斷線／登入逾時**：連不到伺服器 → 明確「連不到伺服器」＋重試（啟動時亦同）；瀏覽器離線 → 頂端紅色橫幅；任何 API 回「請先登入」→ 回登入頁並說明「登入已逾時」。首頁、平面圖查詢失敗顯示錯誤＋重試，不再一直「載入中」。
