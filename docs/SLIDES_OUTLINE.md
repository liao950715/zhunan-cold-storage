共 12 張；Demo 佔 3 分鐘，其餘每張 20–40 秒。粗體是每張要講的一句話。

### 1. 封面
- 竹南冷凍倉儲庫存管理系統
- 組別／組員／日期
- 線上：zhunan-cold-storage.liao950715.workers.dev｜GitHub：github.com/liao950715/zhunan-cold-storage

### 2. 案例與痛點（0:00–0:50）
- 兩座冷凍庫、約 20 種蔬果、盛產期進貨、非盛產期出貨
- 貨種增加、人力減少 → 隨意堆放 → 出貨找不到
- **「明明記得有五籠甘藍菜，卻找不到，後來發現壞了」**
- 六個問題：位置不明、找不到、靠記憶、舊貨久放、損壞沒登記、差異難追、都靠李太太

### 3. 六輪需求決策（0:50–1:40）
- 第 1 輪：介面選 B+（有平面圖、點選操作、不拖曳商品）
- 第 2 輪：一儲位一商品、可多批次；每商品自己的單位；FEFO 建議＋人工確認
- 第 3 輪：工作人員也能新增商品；雙入口入庫
- 第 4 輪：Dashboard、搜尋定位、可編輯平面圖
- 第 5～6 輪：容量依儲位×商品、直接報損、盤點需核准、部分搬移、帳號登入
- **核心設計：商品 → 批次 → 儲位三層，總量不夠用**

### 4. 系統做什麼（1:40–2:00）
- 11 個頁面一張圖：首頁／查庫存／平面圖／入庫／出庫／搬移／報損／盤點／紀錄／商品／設定
- 兩種角色：工作人員（日常作業、編輯布局）、管理員（核准盤點、管帳號）

### 5. 架構（2:00–2:20）
- 前端：React + TypeScript + Vite + Tailwind + React Konva（平面圖）+ PWA
- 後端：Cloudflare Workers + Hono + **單一 Durable Object（SQLite）**
  - 真正的資料庫交易 → 庫存與紀錄同生同滅
  - 單執行緒 → 多人同時操作天然序列化，不會扣成負數
- 一個 Worker 同時提供 API 與前端，免費方案可跑
- 安全：同步碼配對裝置（節流）→ 帳號登入 → 後端強制角色

### 6. 老師的五階段流程怎麼落實（2:20–2:40）
| 階段 | 交付 |
|---|---|
| 環境搭建 | Git、AGENTS.md、npm workspaces |
| 產品設計 | 六輪決策 → PRD v1.0 |
| 技術設計 | TECHNICAL / DATABASE / UI_DESIGN / TEST_PLAN |
| 產品實現 | Stage 1–4，每 Stage 一個 commit＋測試 |
| 人工驗證 | MANUAL_VERIFICATION.md（組員親自操作） |
- **AI 幫寫，但規則來自 PRD；測試沒跑過不算過**

### 7. Demo ①：找貨（2:40–3:10）
- 首頁打「紅」→ 即時建議 → 查庫存 → 「在 A 庫平面圖標出位置」→ 黃色「搜尋結果」
- **李太太的問題：知道有貨，現在一秒看到在哪一格**

### 8. Demo ②：入庫 30 → 搬移 5 → 出庫 10 → 報損 3（3:10–5:00）
- 入庫：選甘藍菜 → 30 → 分到兩個儲位（故意填 5 → 「還有 5 籠沒分配」擋住）→ 核對 → 確認
- 搬移：平面圖點 A-01-03「搬到別的儲位」→ 5 → 點 A-01-05 →「① 從這裡搬出／② 搬到這裡」→ 確認（總量仍 30）
- 出庫：10 → 圖上「從這裡取」、最早到期優先 → 確認
- 報損：點 A-01-04 → 3 → 壓損 → 確認
- **查庫存＝17 籠，紀錄頁五類可查、每筆有前後數量**

### 9. Demo ③：盤點與權限（5:00–5:40）
- 工作人員提交盤點（A-01-01 實盤 10）→ 沒有「核准」鍵；直接打 API 也是 403
- 管理員：「有 1 張待核准」→ 核准 → 紀錄多一筆「盤點調整」
- 提交後庫存若變動，核准會被擋（避免舊盤點蓋掉新出入庫）

### 10. 為中老年使用者設計（5:40–6:10）
- 大字（18–22px）、52px 按鈕、左側固定選單、單欄步驟
- 「目前步驟」提示列跟著捲動，告訴你現在該做什麼、還差什麼
- 每格都有文字：空位／有貨／已滿／搜尋結果／✓ 已選這裡，不只靠顏色
- 錯誤訊息說原因＋怎麼辦：「A-01-04 最多還能放 20 籠，請減少數量或改放其他儲位」
- 文字放大開關；手機可用

### 11. 測試與證據（6:10–6:50）
- 後端 API／整合：**45 項**（含並發 20 筆只成功 10 筆、重複提交只扣一次、DB CHECK 拒絕負數）
- 前端單元：5 項；Playwright E2E：**10 項**（整合情境、平面圖、權限、手機）
- 人工驗證表：AT-01～25（已填結果）
- Git：24+ 個 commit，每 Stage 一筆；未 force push
- **測試都是實際跑過的，報告附輸出**

### 12. 限制與下一步（6:50–7:30）
- 限制：Canvas 無鍵盤焦點（用下拉替代）；手機平面圖左右滑動；示範資料非公司真實數據
- 未來：QR／條碼掃描、多公司（每公司一個 Durable Object）、離線快取
- **結尾：以前是「我記得有五籠」，現在是「甘藍菜 17 籠，在 A-01-03、A-01-04、A-01-05，最早 10/23 到期」**
